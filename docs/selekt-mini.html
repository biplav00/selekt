Rules of the mini

  • Inspect = one locator. Best only, with Copy and Pick new (re-arms the picker). No list, no history, no meta strip.
  • Manual = textfield + two buttons. Test probe and ×. No suggestions dropdown, no hint wall — the verdict line appears only after a test.
  • Always escapable. The ⤢ button restores the full sidepanel with all state intact (same locators, same probe text).

How it maps to the app

  • Header button swaps meaning: in full panel it minimizes into this dialog; in the dialog it expands back. No new window, no sidebar close — one panel, two presentations.
  • State needed: a single mini: boolean flag next to the existing settings. Everything else (locators, probe, histories) is shared.
  • Approve this and I'll port it: mini view component + header swap, same hooks, zero new permissions.

When Bar wins

  • Mouse-driven copy-paste loops: ⌖ pick → lock → ⎘ copy → paste → ↺ reset. One row is the whole UI — toggling tabs only switches views; clicking the active ⌖ re-arms the scan.
  • Manual collapses to a single-line field + go button — Enter tests, same as everywhere.
  • Resizable: drag the corner grip — the locator collapses to ellipsis down to 230px. In the real panel it flexes to whatever width Chrome gives it.
  • Trade-off: no visible verdict until you test, no history. Pair with full-panel history for deep work. The × dismisses without expanding (the shipped code keeps it for the same reason — a failed expand must never strand the dialog).

When Split wins

  • Both jobs visible at once: the locked best locator and a scratch probe field. No mode to remember.
  • Tallest of the three (~150px) but still a third of the full panel — the no-tabs honest minimum.
  • Resizable like Bar (drag the corner, floors at 230px) — rows never wrap, they truncate.
  • Expand lives in the micro-strip; state carries over exactly like A and B.
